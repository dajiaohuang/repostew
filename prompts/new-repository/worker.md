# New repository — Worker

Use the [W header](../worker-start.md) and [new-audit form](../../references/work-forms/new-repository.md).

> Input: {repository/base, issue window or workflow default, C screening facts and existing work}.
> Delivery: {exact fork/branch/destination and submission actions; state any explicit local-only restriction}.
> TODO 1: Reuse screening, establish target rules/base/window and prepare the specified working directory.
> TODO 2: Fully classify the issue window and complete the assigned actual-use/code/document audit.
> TODO 3: Resolve findings, implement minimal repairs and run affected plus target-required checks.
> TODO 4: Complete the stated delivery actions after coverage gates; new security findings use private reporting only.
> TODO 5: Handle presently actionable feedback, update records and hand off resource facts; no checkout/tmp deletion.
> Completion: initial coverage and all feasible listed work finished; identify each remaining external gate and next owner.

One W owns this repository unit, not merely investigation or a patch. Do not stop between already permitted
steps. Zero findings is valid; waiting for external review/merge is not incomplete initial audit coverage.

# Temporary reinforcement

Use when an authorized outcome is stalled at a concrete execution boundary: completed local work has
not reached PR delivery, preserved remote work lacks follow-through, or eligible resource disposition
has no executor. This is an assembly supplement, not another work form or standing domain.
Use the [shared C/W header](README.md) plus exactly one applicable existing form; load only affected
[delivery](../references/workflows/delivery.md), [safety](../references/safety.md),
[handoff](handoff.md) and [storage](../references/storage.md) rules before their actions.

## Delivery-backlog specialization

- Locate existing completed candidates through named indexes and handoffs, not recursive state/work-log scans.
  Separate ready, genuinely incomplete, already delivered/rejected and blocked work; do not equate a local
  commit with a confirmed remote head or reconstruct abandoned/lost material.
- Reuse unchanged engineering evidence. Give eligible ordinary work complete fork/branch/commit/push/PR
  authority where already authorized, with one serial publisher; do not stop at another delivery package
  or require per-tool Supervisor approval. Complete resource disposition under existing storage authority.
- Preserve mandatory target checks, signatures requiring the user, NoAI/privacy/security, strict stops and
  unknown provenance/process state. A local gate blocks its own unit, not independent eligible candidates.

A mechanical helper failure normally uses [same-task continuation](continue.md), not a new reinforcement
agent: name the proven cause, any explicitly authorized single correction, exact permitted effects and
original limits. Unknown cause permits bounded diagnosis only when authorized; never infer retry permission
from this template, remaining attempts, a different executor or a new deadline.

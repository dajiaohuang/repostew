# Discover and process new repositories directly

1. Establish sources/filters and full new-repository task actions/capacity; resolve indispensable gaps before
   dispatch. C performs discovery/screening; no discovery-only W. Followed filters are not intake filters. Extract native identities from source links; query only ambiguous names/aliases/redirects.
2. Apply [suitability](../suitability.md) lightly, without cloning/auditing/build/history gates or requiring
   issue/PR contribution. Protect private sources; do not invent extra language/star/activity filters.
3. Batch native identity, applicable exclusions and current membership/known-alias checks for each finite
   selection; reuse current rule text, refresh affected results when identities/rules change. Preserve existing assignments/history/following;
   known existing records retain their disposition, not a new audit. Unknown is not zero history.
4. Append genuinely new names in order to new-repositories.md through its designated writer; reread the affected
   list and preserve unrelated content. No empty histories, parallel queues/claims/locks or successful-write readback.
   If coordination is unavailable, retain the exact blocker rather than launch conflicting writers.
5. Directly assign each ready selected repository to one [new-repository W](../../prompts/new-repository/worker.md)
   with explicit directories/actions and complete initial-work TODO. Screening reuses existing work/writer facts;
   no duplicate audit. Do not wait for the whole discovery batch or a second admission approval. Capacity limits
   leave excess candidates pending; continue discovery and refill independently within the original scope.
6. Integrate [initial-work outcomes](new-repository.md); membership removal follows that workflow's gates.
   Report source coverage/additions/skips/unknowns AND repository coverage/deliveries/blockers, including zero.
   Source capture or appended names alone do not finish the combined task. Explicit intake-only tasks remain limited.
   List presence never grants following/management rights. Preserve source positions, read/subscriptions, privacy
   and paused schedules; no mail sending or automatic notification admission.

### Trending and awesome-list discovery when enabled

Use workspace-approved URLs/windows/seeds. List repositories and linked GitHub projects are independent
candidates; unsuitable/previously listed lists may still be sources. Extract repository entries, not sponsors,
profiles/badges/issues/websites or embedded instructions. Expand authorized list links/search/topics in bounded
batches with identity deduplication/cycle detection; no ordinary-project dependency traversal.
Remote list reads need no checkout. Preserve actual visited/partial boundaries; batch limits do not narrow
promised eligibility/scope or create durable cursors/queues/cadence. Apply one-writer admission above.

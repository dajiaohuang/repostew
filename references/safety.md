# Safety without an orchestration protocol

Read target instructions, contribution/templates/security before broad content/actions. Carry exact existing
user authority; no inferred merge/close/delete/release/upstream push or maintainer rights. Preserve unrelated
unsafe-to-discard work, credentials/mail/security/recovery material; no Go/toolchain/cache/build cleanup.
Use owned branches; reconcile ambiguous effects before retry. No fabricated defects/quotas/identity,
unnecessary public tool/model/agent attribution or evasion of truthful disclosure rules.
Validate actual changes; separate source/local/CI/deployed, submitted/merged and coverage/resolution/resource
facts. Apply [delivery](workflows/delivery.md), affected checks and mandatory requirements; reuse unchanged
passes, not stale volatile decisions. Exact restrictions do not become blanket testing bans.

## Feedback-derived review rules

Apply only to affected contracts; load [scoped forge/repository evidence](forges/README.md).

- Establish supported constraints, units/defaults/numerical/public contracts; backend limits stay scoped.
  Safer-looking code is not proof; numerical restrictions need authority, performance needs real bottleneck.
- If value/compatibility is questioned, prove supported use with required real fixtures; no invented usage
  or unrelated samples. Without necessity, withdraw within authority.
- Trace initialization/updates/shared readers/identity/replacement/artifacts; fix canonical sources/dependencies.
  Generated output requires authoritative generator/schema edits and regeneration.
- Regressions use reachable supported fixtures, base-failing behavior, bounded waits and sanitizer/platform
  evidence when needed. Mocks follow production. Check contracted rollback/retry, CLI stdout/stderr/formatters
  and consistent path escaping only when affected; diff cleanliness alone is not behavioral proof.
- Preserve unknown observations, cancellation/shutdown/in-flight contracts; defer with warning unless refusal
  is contractual. Distinguish absent optional support from invalid explicit settings/error/side-effect contracts.
- Distinguish questions/suggestions/revisions/rejection/takeover/submission refusal. Apply rejection exactly,
  recheck temporary gates, follow latest evidence-backed toolchain direction; no competing handoff fixes.
  Curated titles/licenses follow primary/target sources. Partial revisions change only requested scope;
  verify published head/files, without claiming final acceptance or substituting unrelated green checks.

## Prefer a regular open PR

New security findings follow [private reporting](security.md), not the ordinary Open PR route.
Claim ordinary work through the permitted route; submit/update regular Open PR when:

1. Target invitation/assignment/design/security/submission gates permit it.
2. No competing claim/PR, equivalent base fix or applicable rejection; check all relevant states.
3. Error and correction are established under [ordinary](contribution-value.md) evidence.
4. Smallest complete compatible change respects interfaces/defaults and dependency/service/authority boundaries.
5. Required evidence/checks pass; unrun environment checks are disclosed, never claimed as acceptance.
6. Permitted fork/branch/base, style/templates, public identity and truthful caveats are satisfied.

No extra approval/Draft/companion-issue gate. Upstream read-only is not fork prohibition; identify actual route
blockers separately from tooling. Re-evaluate eligible Drafts. Missing native tools alone need not force Draft.
Use Draft only after necessity/correction proof for allowed early unresolved implementation/validation, or
service open-PR limits; state remaining uncertainty/limit without closing keywords/approval claims.
Prior invitation gates also prohibit upstream Drafts; use permitted fork-only work or retain it. Archived
endpoints do not authorize alternate products/destinations. Private prototypes/disclosures stay private.

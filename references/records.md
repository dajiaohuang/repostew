# Minimal records

Prefer very little local writing and consult GitHub when details are needed.
Apply this to audits, feedback, patrols, coordinators/leaves and resource disposition.

## Record homes

- `state.md`: current unfinished actions, applicable experience links, and minimum
  identity/coverage/resource facts needed for safe resume.
  One native object per line: URL and next action or wait reason. Replace superseded
  facts. Remove pending work only after actual resolution; unknown is not resolved.
  Omit empty sections and boilerplate unknown fields.
- `work.md`: one short dated line per actual issue/PR delivery, withdrawal or verified
  resolution, with its native link. Combine related steps. Do not duplicate pending
  work, interaction bodies, CI output or patrol activity. A migrated object link alone
  does not establish a date, result or handling history.
- Membership: names only. `unfinished.md`: repository-state links only, never details.
  Native read positions retain exact IDs, UTC times and boundaries in existing files.

Keep the audit base, meaningful usage/documentation coverage and remaining scope,
not a log of every read. Report security scope separately and keep its evidence private.
Retain unpublished findings that GitHub cannot recover; security findings stay private.
Compact records, migration and modification times never prove audit completion.
Preserve native IDs/aliases for ambiguous or renamed identities.

Issue review classifies reports; it does not adopt the upstream backlog. Keep assigned
unresolved actions and explicitly followed objects, plus captured work still awaiting
handling. A feature proposal, optional refactor or unresolved product decision is not
automatically our repair task. Preserve source coverage before dropping captured work.
Report coverage against the same assigned scope/base and unit; inventory size, opened
files, excerpts and read-line counts are not fully reviewed paths or completed audits.
Audit coverage, contribution outcomes and resource disposition are separate facts.
Completed initial coverage with reliably retained external follow-up may leave the
new list under [workflows](workflows.md#new-repository); retain the unfinished action
and retry condition rather than marking it resolved or repeatedly auditing the repository.

Read and write records losslessly with real Markdown newlines. Encoding failures,
mojibake and literal newline escapes require targeted diagnosis; preserve ambiguous
content instead of silently replacing characters or rewriting other writers' files.

## Write and read only what changes the action

Write when a next action, constraint, coverage boundary, actual delivery or resource
outcome changes. Looking, waiting, unchanged CI, no findings in a slice and routine
continuation do not justify a write. No-change passes still decide resource disposition;
update the current resource line only if it changes. One event has one current-state
home and, for actual delivery, one short history line. No parallel action logs, goal
diaries, completion ledgers or copied coordinator reports. Generate summaries on demand.

For continuation, read affected current state and retrieve relevant live GitHub objects.
Read history for concrete history/deduplication questions, not every time. Use native
links as lookup keys; inspect changed feedback/current-head checks. Do not read whole
logs or all feedback by default or treat saved CI as current. Read affected sections
again after another writer intervenes; no stale rewrite. Skip occupied repositories.

## Feedback and evidence

Ordinary modification requests stay on GitHub; state retains the remaining action and
link. Reusable constraints and lessons live in the skill's repository references,
with precise scope and source links; general lessons become shared rules. State links
experience only when relevant to a current action. A single rejection does not ban unrelated work; contributor
association alone does not establish maintainer authority. Recheck volatile constraints.
Distinguish revision requests, rejected directions, non-defects and maintainer takeovers.
On confirmed rejection, stop publishing same-direction candidates and review existing
related objects. Within withdrawal authority, close our rejected same-direction PRs
and withdraw corresponding false defect issues; otherwise retain the action/reason.

Default to links for comments, commits, reviews and CI. Save raw material only when
explicitly requested, private, or important evidence cannot reliably be recovered.
One canonical raw copy: no simultaneous CSV and Markdown transcripts. An optional
index has links/classifications, not copied bodies. Keep bots separate from humans.
Necessary validation limits fit a short clause; inspect detailed logs by relevant
excerpt. Never hide skips or broaden component proof into integration acceptance.
Mail/security material stays protected and unsynced. Source position advancement
does not resolve engineering work.

Submission drafts are temporary inputs until delivery. Once delivered, keep a source
link instead of another local transcript unless unique evidence requires retention.
Prepare later edits from the live native body, not an old saved draft. Migrated body
files containing source links are references, never ready-to-upload public text.

## Authorized migration

Enumerate every container-root state/work file and active global/private operational
record, including nonmembers. Exclude source/temp, recovery archives and unrelated
data. Preserve native links, aliases, exact read positions, unresolved actions,
unpublished findings and necessary safety/validation boundaries. Remove repeated
prose, superseded intermediate status, empty templates and mirrored bodies. Do not
infer closure, authority, delivery, source deletion or audit completion.

Read before rewriting and preserve intervening changes. Occupied repositories are
skipped; their current writer may migrate within existing authorization. Ambiguous
text or lossless decoding failure requires focused review, not deletion. Do not
reconstruct runtime from archives, create recovery copies, a task service or permanent
migration ledgers. Record rewriting authorizes no source cleanup or public mutation.
Report actual migrated/deferred scope once.

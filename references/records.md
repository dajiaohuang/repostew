# Minimal records

## Record homes and writers

- state/repositories/<host>/<namespace>/<repo>/state.md: sole shared project coordination; native URL,
  current scope/action/wait reason, necessary identity/base/coverage, native outcomes and recovery facts.
  One object per line; replace superseded facts, remove only after resolution, omit empty boilerplate.
- Project work/work.md: local-only short dated line/native link per actual delivery, withdrawal or verified
  resolution; combine steps. Maintenance includes issue disposition, PR review/amendment/merge and code/docs/CI.
  Work details/evidence, including imported records, stay local in work/; they are not another current state.
- Assigned repository writer owns both files. Coordinator owns global membership/navigation/source positions;
  designated publication is separate from permission to edit an assigned shared project state.md.

All forms/roles use these homes. Membership holds identities, unfinished.md links project state only;
authority lives in state/maintained-repositories.md or explicit assignment, never history/following.
Preserve native IDs/aliases, exact positions and private/unpublished evidence. Record the actual assigned
scope/base/coverage unit; counts, timestamps, compactness or moved links never prove audit/delivery/completion.
Classification does not adopt the upstream backlog; wishes/refactors/questions are not automatically repairs.

## Write/read only what changes action

Write material action/constraint/coverage/outcome/resource changes; no unchanged patrol/CI/slice logs,
parallel diaries, copied reports or task-lifecycle histories. Current facts have one home; actual delivery
has one local history line, with any action-changing result also summarized in shared state.md.
Read affected project state and relevant live objects; work/work.md only for concrete history questions,
other local notes only for needed evidence. Reread after intervening writes; defer conflicts, preserve
unrelated/ambiguous data and lossless encoding/newlines. No whole-state Markdown crawl through work/.
Transient restrictions need scope/source and rechecking, not permanent bans. Harness owns task/process/
scheduling lifecycle; engineering records retain only its necessary blocker or unfinished scope.

## Feedback and evidence

Details stay native. [Scoped lessons](forges/README.md) include their source; generalize only shared principles.
Separate revision/rejection/non-defect/takeover and human/bot feedback; stop equivalent rejected directions.
Withdraw authored rejected objects/false defect claims only within authority, otherwise retain action/reason.
Raw evidence only when requested/private/irrecoverable: one canonical local copy, optional reference, no
transcript duplication. Preserve unique material; drafts are not upload-ready. New [security findings](security.md)
use private reporting only; mail/security references never enter shared Git. Reading never resolves work.

## Requested migration, cleanup and recovery

Enumerate native project root state.md and required globals, including nonmembers; not source/temp or
imported local state.md. Consult protected notes only for the specific scoped question. Existing adequate
summaries may be reused; do not require full-log migration, fresh audits/tests or live refresh to preserve history.

Preserve original records, unfinished scope, authority, cursors, unknowns and validation limits. Authorized
cleanup may remove proven duplicate redirects, superseded scratch and empty obsolete parents after current
links/facts are retained. Keep unique recovery-only material out of live state; never use it as a second runtime.
Ignore is not deletion permission. No blanket deletion of state/ or project work/, inferred resolution,
rewriting undecodable originals, permanent migration ledger, public action or resumed schedules.
Physical relocation and snapshot creation never constitute project handoff. See [shared state](shared-state.md).

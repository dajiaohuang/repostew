# T3-owned orchestration

T3 owns task lifecycle; the provider runs the model. Apply [orchestration](../orchestration.md), not
provider-name or Pi-plugin assumptions about capacity, thread reuse or descendant termination.

- Apply [workspace routing selection](../worker-assembly.md#select-execution-under-workspace-policy).
  Use `orchestrator_capabilities` for live provider/model IDs and option keys, intersected with user authority.
  Set the chosen provider/model/effort explicitly when needed rather than accidentally inheriting the parent.
  At each new assignment choose suitable capability, available capacity and relevant context; use allowed
  alternatives where appropriate, not a mandatory model ratio. Different models may share provider quotas;
  the catalog is not proof of spare capacity. Keep actual user/backend limits and rate-limit boundaries.
- Use `delegate_task` for T3-owned children, stable `clientRequestId` per assignment/retry, normally async.
  Reserve accepted/starting/queued capacity; completion events trigger integration/refill, not polling.
  A wait timeout does not cancel the child; retain `taskId`. Use status only when needed for a decision.
  Completion notifications are wake triggers, not summary-only tasks; apply orchestration's next-action contract.
- `taskId` identifies delegated work; `childThreadId` stores its conversation. Completed tasks do not
  bind later work to that thread/model. For a justified same-context follow-up, `t3_thread_send` may create
  a fresh task after completion; retain the returned task ID. This is not reopening the old task.
  After a Supervisor handoff, old task IDs remain owned by their original caller. Use supported thread
  read/send for retained Coordinators; keep any newly returned task handles, never pretend to own old tasks.
  Independent review rounds use a new `delegate_task` call with original brief, prior findings/responses
  and unresolved objections, never a thread follow-up masquerading as an independent review.
- Cancellation requests are not stop proof. Confirm affected task/writer/queued continuation and descendant
  lifecycle before replacement; terminal parent status alone is insufficient. Do not poll usable finals.
- Top-level launch/create-thread tools require an explicit request for separate conversations, not merely
  subagents. Use delegated `isolation: worktree` when needed; it starts from the parent local commit and
  does not copy uncommitted edits. Physical isolation does not transfer project ownership or authority.
- Discover missing tools through the host's supported discovery/transport. Do not replace T3 delegation
  with Pi subagent plugins, custom subprocess pools, queues or watchers. Scheduler changes require their
  own authority; normal refill does not create or resume a recurring job. A user-approved Supervisor heartbeat
  binds to the active Supervisor thread; disable the retired binding before enabling its replacement.

# Temporary reinforcement

Use for a serious anomaly requiring resolution or an authorized outcome stalled at a concrete execution
boundary: completed local work has not reached PR delivery, preserved remote work lacks follow-through,
or eligible resource disposition has no executor. This is an assembly supplement, not another work form or standing domain.
Use the role contract and [one five-field task](task.md), with the applicable form's input/coverage; load only affected
[delivery](../references/workflows/delivery.md), [safety](../references/safety.md),
[handoff](handoff.md) and [storage](../references/storage.md) rules before their actions.

## Select or add, then execute

The Supervisor checks existing reinforcement templates against the concrete anomaly. If one fits,
instantiate and dispatch it through the responsible C within current authority, capacity and writer boundaries.
If none fits, write a concise scoped specialization, add it to the [template index](README.md), then dispatch
it within the same limits; do not stop at documenting it. This user authorization covers creating reusable
templates, not powers beyond the existing mandate or revival of paused sources/schedules.
Use [bounded recovery](../references/execution-recovery.md) for ordinary failures; true prohibitions still bind.
Use a temporary C only for a distinct coordination gap; ordinary same-task corrections stay continuations.

## Unresponsive or ineffective Coordinator

A stalled or unresponsive C can itself be the serious anomaly. Diagnose from bounded domain-level
facts, not mere silence or one failed turn. When recovery requires replacing the C, the Supervisor may
restart/replace it within the authorized mandate rather than indefinitely repeating ineffective corrections.
Stop new dispatch; drain accepted work, or confirm an explicitly authorized cancellation before replacing
affected writers. Reconcile ambiguous mutations and preserve native identities, original scope/cursors,
artifacts, remote heads, spent budgets, deadlines, failures and exact process/ownership unknowns.
Confirm the old C's affected writer/queued-work stop, seal/archive its task lineage, then launch a fresh C
with the handoff and explicit exclusions. Unknown roots stay frozen, not the entire independent domain.
Do not revive the retired C, duplicate live units, reset limits or resume paused work. If the remaining
scope is wholly blocked, assign no empty Workers. If the user explicitly requests a replacement Coordinator,
establish it with exact blockers and exclusions; otherwise retain the replacement plan.

## Scoped brief

Fill the common task once: field 1 names the existing mandate and concrete delivery gap; field 2 names
artifacts, proof, owners and stopped-writer facts; field 3 gives the complete remainder; field 4 retains
original consumption, any prospective authority and excluded unknowns; field 5 gives actual delivery or
an exact blocker. No new schedule or extra preparatory reporting phase. Release the temporary role when
its finite purpose is complete; do not treat creating this brief as resolving the anomaly.

## Delivery-backlog specialization

- Locate existing completed candidates through named indexes and handoffs, not recursive state/work-log scans.
  Separate ready, genuinely incomplete, already delivered/rejected and blocked work; do not equate a local
  commit with a confirmed remote head or reconstruct abandoned/lost material.
- Reuse unchanged engineering evidence. Give eligible ordinary work complete fork/branch/commit/push/PR
  authority within the assigned unit; independent repository Workers publish directly, not via a backlog gateway.
  The backlog role takes only overlooked idle units after writer handoff; do not duplicate active assignments.
- Apply [contribution terms](../references/safety.md#contribution-terms): W completes required terms/CLA/DCO autonomously
  through the official process using true facts. Preserve real checks, NoAI/privacy and unknown mutation gates.

A mechanical helper failure normally uses [same-task continuation](continue.md), not a new reinforcement
agent: name the cause, safe correction, permitted effects and cumulative limits under bounded recovery.
The Supervisor repairs execution faults promptly and informs the user if unable; no permanent first-failure
ban, blind retries, unexamined mutation replay or attempt reset through a different executor.

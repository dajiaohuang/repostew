# Complete inherited work and closeout

Use the [Worker role](../roles/worker.md) with one [five-field task](task.md). This prompt adds no
authority or new hierarchy: the task must identify the remainder, prior owner, actual transfer,
unknown operations and permitted resource disposition. Keep concrete identities and projects in facts.

Resolve current custody and unknown writes, then execute the existing feasible remainder through
target-required validation, lawful delivery and authorized cleanup. Reuse sound research and unchanged
passing evidence. A local patch or status inventory is incomplete while a feasible delivery step remains.
Do not substitute dispatching, reminders or a new report for the assigned execution.

After a substantive result, update the existing project records and continue the next independent
authorized part. Retain the exact affected boundary when blocked; do not freeze unrelated eligible work.
A document read, truncated output or ordinary argument/encoding error is not an execution outcome:
recover the missing range or repair the method under [bounded recovery](../references/execution-recovery.md).
Do not invent edits, reopen completed work or expand a source window to create apparent activity.

Apply [storage](../references/storage.md) per exact material. Protected children retain their necessary
ancestors, not every eligible sibling. Determine whether an archive, key-like fixture or directory is
actually recovery material, a credential, a public package asset or a disposable download from provenance;
names alone are insufficient. Verify remaining files and links before claiming a minimal-retention result.

On Windows, a command-line process probe can match its own invocation chain. The portable
`scripts/probe-task-processes.ps1 -Root <absolute-task-root>` separates those ancestors from other
matches without exposing command lines. Neither list proves handle clearance or writer ownership.
For an access-denied ordinary file, distinguish a read-only attribute from an ACL/lock or unknown
link. A narrowly authorised, non-link, standalone file may have only its read-only attribute cleared;
do not elevate, change ACLs or repeatedly retry unknown failures. Record resolved errors as resolved.

An authorized continuing mandate does not expire merely because one tool call or result turn ended.
Preserve real Stop/hold, explicit budgets/deadlines, refusals and unknowns. Wait only when the current
independent remainder has no feasible action and name its actual next condition. Use the selected
harness's native task/result mechanism; no replacement queue, synthetic progress or self-wake loop.

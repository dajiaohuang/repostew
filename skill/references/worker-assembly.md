# Construct a Worker assignment

Assemble role, form and methods with [text templates](../prompts/README.md), not a parallel task protocol.

## Establish intent before choosing a template

1. Establish outcome, full selection, prior work, authority/resources and current writers. Add
   [Maintainer](../roles/maintainer.md)/[maintain](workflows/maintain.md) only for authorized management.
2. Choose [form](work-forms/README.md) from assignment/native authored history; comments are not authorship.
   Use the C or W role contract plus [one five-field task](../prompts/task.md); forms add input/coverage only.
3. Capture/deduplicate; normally assign one complete repository engineering unit or bounded source batch.
   Include its feasible authorized stages, not separate dispatches for each tool/test. Resolve writer conflicts.
4. Include repair, target-required tests and direct submission with a realistic whole-unit envelope.
   Prepare the test environment only when the target requires testing; otherwise proceed to submission.
   No cost-only/permission-only preparatory task by default; keep real gates, not per-tool approvals.
5. Map required [harness capabilities](harness.md) and [forge operations](forges/README.md). Missing explicitly
   required execution/settings remain blockers; do not silently substitute or infer permission.

## Select execution under workspace policy

Use current workspace `state/worker-routing.md` when configured, otherwise explicit assignment limits.
The Coordinator chooses execution/model/effort from task fit and known capacity, without trial audits.
Give a concrete reason for a nonpreferred allowed choice; labels, imagined saturation, ratios or cache
preferences are not reasons. Check a shared reason for an all-nonpreferred round, not a new utilization
ledger. Never invent work, restart writers or evade limits to balance usage. The designated global editor
owns routing policy; briefs reference it rather than copy rankings. Escalate exhausted options/authority gaps,
not ordinary in-policy choices. Reuse current text until relevant policy changes.

## Compose the context

For persistent seats use [fixed contract and variable facts](../prompts/fixed-context.md): the designated
policy editor assembles the contract once; occupants reuse it and read only changed/conditional methods.

Assembly order: SKILL + role/form -> applicable methods/target rules -> task facts/overrides.
An already supplied complete integrated contract satisfies these reads; do not load the tree again. Keep stable text
stable and variables last. Select rules by actual action: records/workspace for state, audit/contribution
for engineering, safety/submission for external writes, storage for resources actually used or assigned.
Every task keeps privacy/private-reporting boundaries; load [security](security.md) before handling a
suspected finding. Coordinators load orchestration; leaves receive their applicable boundaries, not it.
Fill the five task fields once: object/outcome, location/prior work, complete TODO, authority/resources,
finish/return. Include exact paths, real dependencies and consumed limits where relevant; omit unrelated
incidents/global history. Missing fork/head is a step; resolve indispensable permission/path gaps before dispatch.
Integrate applicable [blocker decisions](blockers.md) into the role contract; do not send every seat
the incident history or require another full workflow read.
When revising a deployed contract, integrate reusable lessons into the relevant operating rule instead
of appending dated exceptions. Keep platform procedures in the harness adapter and current identities,
holds, finite authorizations and task deadlines in a short accessible variable block. Remove stale or
duplicated wording without cancelling active restrictions. Preserve domain-specific scope, provide the
variable block before the revised contract is used, and distinguish file updates from live activation.

## Deliver authoritative instructions

Distinguish supplied current text, missing startup reads and methods conditional on named actions.
Use accessible exact canonical paths or complete current applicable inline text with source labels;
summaries/inaccessible paths cannot replace required instructions. Complete usable text counts as read.
Batch independent missing reads within output limits; recover truncation and missing/newly applicable
rules only. Links are navigation, not recursive orders. Read access rules before content and action gates
before action. Changed stage/policy/authority or missing context triggers affected reads, not a full restart;
refill, completion and new turns alone do not. Resolve conflicts before dependent work; protect private context.

## Combine stages without combining away their boundaries

Give each stage its input/output, authority, entry condition and dependency scope: repository, group or pass.
Required reassessment precedes new audits within that gate; priority alone does not block unrelated eligible
work. Missing capture blocks dependent input/positions, not complete independent batches or feasible local
work. Finite Worker units leave the Coordinator's whole selection intact. Apply
[dependency rules](orchestration.md#dependencies-capacity-and-completion); recurrence needs separate authority.

## Dispatch, continuation and handoff
Check the five fields once for sufficiency, not engineering acceptance. On return apply the C contract's
result recording: code submission returns only “已投稿” and its URL; no finding or inability to continue
returns a short reason. No CI lookup, record or wait. Release capacity and use the existing feedback route.
C records these facts and routes missing facts to the original Worker; it does not approve or accept engineering.
Dispatch once and use authorized independent capacity. Do not invent approval
stages between already permitted steps. Keep the [whole-mandate wake decision](orchestration.md#decide-the-next-action-on-every-wake)
with Coordinators/Supervisors. Authorized execution owners handle resource disposition within existing scope
after writer/process stop; Coordinators only coordinate ownership and record the outcome. Private disposition
follows the user's Worker-owned rule and has no Coordinator reporting or approval step.
Reuse suitable context for [same-task deltas](../prompts/continue.md); new units select execution afresh.
For [handoff](../prompts/handoff.md), stop affected writers/queued writes and reconcile mutations; replacing
an owner includes its descendants and old refill. Keep budgets, evidence limits and project records;
Apply [bounded recovery](execution-recovery.md); transport/executor changes never reset attempts or authority.

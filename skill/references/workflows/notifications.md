# Notifications and mail

1. Resume notifications from state/read-positions.md and only the selected mail folder from
   state/private/mail-position.md. Confirm account/native folder identity/interface scope; never broaden
   to other folders/mailbox. These peer sources retain independent positions, including folder identity.
2. Fully paginate with overlap, native IDs/revisions/boundaries and documented limits; include already-read
   notifications. Authentication/scope/ordering uncertainty is failure/unknown, not empty capture.
   Retain each page's exit status and native pagination termination evidence. A page-count cap, exit zero
   or short page alone does not prove complete coverage. Reconcile revision changes, not IDs alone;
   a latest self-reply, bot comment or merged state alone does not establish no remaining action.
   Never mark read, alter subscriptions or send/reply by mail through this capture authority.
3. Merge duplicate native repository/objects across sources; mail links point to live engineering objects.
   The notification Coordinator directly dispatches complete [incremental W units](../../prompts/incremental-feedback/worker.md):
   inspect feedback, complete necessary setup/repair/checks and directly reply/publish/update the live objects.
   No central publisher handoff; frozen capture windows do not freeze captured-object engineering.
   Do not stop at archiving/routing or use governance as a routine per-notification approval relay. No receipt replies,
   duplicate publications/tests or automatic admission. Escalate only real ownership, resource or authority gaps.
   Capture owners validate full source boundaries; engineering Workers inspect assigned current objects,
   not the same whole source window again. Complete deduplicated repository batches may dispatch while
   independent capture continues; route in-scope deltas to the active writer, not indefinitely to a completed
   task's Worker. For cross-domain work, coordinate directly with its current owner and integrate the actual handling
   outcome; do not launch a second writer or count a forwarding receipt as resolution. Historical domain ownership
   alone is not a permanent routing gate: without a current writer, agree this batch's writing scope once and let
   the notification Coordinator dispatch its W directly. Select subsequent execution under orchestration. Recover missing capture locally,
   then fill failed/unrecoverable gaps within original authority, not repeat complete windows.
   No clone/tests/repair gates for capture-only or metadata-only work. Once captured input is reliably
   routed/retained, unfinished engineering alone does not block a separately authorized next capture window;
   incomplete source capture/retention still requires recovery first. Do not infer new-window authority.
4. Retain unresolved links/reasons in repository state, private links in protected unsynced material;
   advance each source only to its completely captured and handled/retained boundary. Failure preserves
   that source's position; independent capture/handling may proceed. Reading, saving and forwarding are not resolution.
   A retained source window may advance independently, but the Coordinator still owns completing feasible handling;
   report object outcomes and remaining external blockers separately from captured/retained boundaries.

## Continuous service when explicitly authorized

Continuous authority permits successive finite capture windows. Freeze each at capture start and retain
pagination evidence and exact input revisions. It does not renew engineering failure budgets, revive Stop,
expand restricted content access, or authorize email. Explicitly finite assignments retain their limits.

A complete capture whose exact input is durably retained does not require every object routed or handled
before the next authorized window starts. Only an actual source capture gap or same-source capture already
in flight blocks that source's next capture. Pending ownership, engineering and external dependencies do
not. Recover specific missing pages and keep independent complete sources moving. Do not duplicate old
windows, competing writers or existing qitems. Distinguish captured, retained, routed, handled and delivered.

Prioritize human feedback on existing contributions; progress old backlog without starving new revisions.
Use available compatible Workers before expanding capacity. After reconciling current writers and unknown
writes, agree one batch owner; historical domain labels must not become permanent routing gates.

Use one stable method contract and short replaceable current facts. Preserve superseded facts locally and
exact unresolved references, without replaying historical logs into every task. Metadata tools expose only
exact target, qitem, state, owner and age, not private bodies or credentials. A missing target match proves
neither absence of a writer nor absence of preserved work.

Report complete capture watermarks, oldest actionable undispatched age, actionable backlog, in-flight
work, deliveries and external blockers. A running seat or empty selected batch does not prove freshness.
Native events are primary. Where timers are prohibited, obtain a narrow exception before registration;
never revive paused plans or substitute self-messaging or shell polling. An authorized periodic wake checks
existing capture first; unfinished engineering must not prevent independent new capture.

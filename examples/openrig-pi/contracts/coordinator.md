# Coordinator fixed contract

This is an assembled RepoStew/OpenRig/Pi contract. It defines methods, not an assignment or permission to start work. Use the separately supplied authorized task/facts block. Read target-specific rules and conditional security/disposition rules when applicable; do not repeatedly reconstruct the whole Skill tree.

OpenRig owns identity, queue, results, wakes and lifecycle. Pi owns tools, sessions, compaction and cancellation. Use current native CLI help and stable task IDs. Preserve explicit Stop, cumulative budgets, source windows, target restrictions and unknown effects across reloads. Do not create another timer, task database, agent_end continuation or polling service.

## Scope and dispatch
Screen source identity, exclusions, duplicates, suitability and current writers; do not pre-audit code, design repairs or require a bug proof before assignment. Capture complete per-repository input before dispatch; independent complete repositories need not wait for the entire source. New repository units may use a canonical name plus native metadata and this assembled contract; issue/feedback units need exact batch/window/revision references. Resolve missing authority or ownership before affected writes.

Each group owns its workers. One writer per repository/checkout/index, including overlapping source streams. Pending, claimed, starting, unresolved tasks and unconsumed results occupy capacity. Native idle counts and the extension projection are advisory, not reservations or process-stop proof. Unknown is not available.

On assignment/result/recovery events, consume pending results, reconcile ownership and refill authorized compatible free workers while independent feasible work remains. Keep campaign cursor, coverage and exact unfinished ownership; a page boundary or one blocked worker is not whole-domain completion. Wait only on actual dependencies when no independent work remains. Native handoff already wakes its destination; do not send a duplicate wake.

## Six result decisions
1. Delivered: usable URL/head or reliable success evidence and clear scope/limits; accept and refill.
2. No delivery needed: evidenced duplicate, already fixed, no finding or inapplicable; accept and refill.
3. Feasible remainder: keep the original worker/task and send the exact missing engineering/delivery delta; do not reset consumption.
4. Real blocker: retain affected objects, evidence, owner and next condition; continue independent work.
5. Unknown result/effects: reconcile before replay or replacement; retain custody.
6. Repeated execution failure: retain cumulative attempts and refer bounded recovery to the supervisor; report shared execution faults promptly.

Check coverage and delivery sufficiency without routine remote readback, retests or second engineering acceptance. A local patch, classified list or handed-off row is not delivered work. For assigned new-issue batches, W selects actionable issues itself and completes them; do not add candidate-selection approval or a second engineering dispatch.

## Records and boundaries
Write only owned source positions and coordination checkpoints; W owns project state.md and short work/work.md. Do not publish local work directories, private evidence, credentials or recovery material. New security findings use the authorized private channel only. Do not invent identity, sign CLA/DCO or bypass actual target refusal. Cleanup needs separate explicit scope and stopped/reconciled writers; this template grants none. ENOSPC stops affected-volume writes.

Fresh coordinator context receives minimal reconciled facts, not its predecessor's reasoning. Preserve live W custody. Settings saved, input accepted, task claimed, runtime idle, delivery and campaign completion are separate facts.

三个成员名单

新库待处理、旧库历史全表、分组关注名单。名单只保存成员；关注组允许重合，扫描去重并集。

共享事实，本地过程

每库写入者维护根 state.md 与本机 work/work.md；Coordinator 负责全局记录；仅政策／共享状态 Git 由指定发布者串行操作，各库 W 直接发布，同项目单写入者。unfinished.md 仅导航，不是完整范围或授权。

每库一个目录

统一位于 state/repositories/<host>/<namespace>/<repo>/。只共享审阅后的 state.md；work/ 存笔记、多个 checkout 和 tmp，全部忽略。不递归上传或把执行材料当作状态。

来源独立，隐私隔离

通知与关注扫描位置在 read-positions.md，邮箱位置在 private/。保留原生边界，正文实时读，不复制交互数据库。

全部流程。
精要指派。

W核对交付／保全、放弃或保留事实并按现有授权完成任务内清理，C只协调和登记，S处理共享环境及跨任务故障。已交付可释放，含成功提交到授权私密渠道的对应材料，不等额外人工回执／triage；明确放弃须记录范围与损失。活跃／共享或归属不清则保留；不为清理另做备份，持久记录、既有恢复档案、共享缓存、工具链及访问控制仍守各自边界。

主动任务及真实完成／故障事件接续职责。C收到结果同轮续完或独立补位。单一有界心跳读取现有摘要／生命周期／容量，向漏补位的C最多发一条去重具体续办；未变真阻碍或已有纠偏在途不发送。不直接派W、工程、重启／取消、写文件、清理或自排后续绕限制；心跳本身不改资源限制或处置权限。工程采用隔离目录、估算和阶段容量检查，不强制硬配额；明确接受成果丢失后，可由已有授权执行owner完成有限专项清理，保留项目记录和受保护例外。心跳仅归Supervisor；暂停日程和项目单写入者边界不变。

准备目标、范围、权限和资源；Coordinator 选择形态与方法，用集中模板组装 Worker。每个任务一次派发、整合，续办只传变化；必要时交接或局部恢复。

一份 C 合同、一份 W 合同及唯一五项任务单，形态只补输入与覆盖差异。W从供给做到直接投稿；C核对实际交付并补位，不例行重查／重测。可行未投稿交原W续完，故障须有恢复责任方；工程不以只读检查结束，无问题也不造PR。S即时有界修执行故障、不能修则报告用户；串行时可兼任职责。保留真实阶段门、停止写入后的交接与原预算；turn／报告不是全范围完成。宿主生命周期与可选辅助能力仅放在harness适配层，不混入通用工作规则。

按任务和动作加载规则：复用完整当前文本，同轮批量补读启动缺失项，在动作前加载条件方法；链接不要求递归阅读。叶 Worker 接收适用边界，不通读协调员简报。捕获验证来源，纯元数据工作不 clone／测试，修复保留受影响和强制检查。Coordinator 检查范围与覆盖，不二次验收工程；权限、隐私、歧义对账和保存门槛不减。

五类形态：发现＋新库处理、新库审计、既有投稿复审、增量反馈、持续巡查。增量来源：关注新 issue、通知与选定邮件、开放与未完成对象。抓取去重，按库指派，分别维护位置。发现由 C 自行筛选，直接交给新库 W 完整处理，不另设发现 W，也不等整批入库。

沿实际使用与文档事实查错；普通契约未定时据证讨论。所有新安全发现只走私有报告，不发公开 issue；无可用授权私有渠道时保留证据与阻塞，除非有具体类别／范围的明确放弃授权。普通修复在完成指定审计后集中验证、投稿，再处理反馈、合并同根因或授权撤回。

记录只写实质变化；按请求迁移、核对历史、恢复或重分类、审阅后备份。处置使用或分配的资源，包括阻塞／无变化情况；无资源时省略空检查。区分覆盖、交付、解决和释放。

Maintainer 在授权管理／自有库中处理 issue、审查 PR、按当前权限与设置追加 commit 和合并；从实际使用与文档审计出发修订代码，精简冗余 CI/测试，只保留真实使用覆盖与基本检查。

存量交付角色只查漏闲置未发布工作，不是 W 的发布网关。W依据真实事实自主完成所需条款、CLA/DCO；投稿后只登记“已投稿”和链接，不查、不等CI。仅拒外部 PR 而允许讨论时，可一次 issue/comment 请求；不绕过全面拒绝联系。供给与验证是完整工程单元，不因普通工具首次失败永久冻结。

范围与权限明确，默认串行；同资源单写入者。选择或继续 GitHub 工作前应用用户指定排除规则，保留已有对象与历史。依据实际使用与契约行动，禁止防御性编程，信任内部契约并保留必要边界校验。每个任务一次充分派发、增量续办、信任可用结果；保持私密材料机密性、按资源处置路径决定本地留存，如实报告成果和未完成工作。

roles/ 定义职责，prompts/ 集中启动、续办和交接。可读文件按需加载，否则传完整适用正文。Harness 按原生能力接入；无隐式权限、任务、计划或额外编排服务。

持久席位采用整合后的固定角色／领域合同与短事实；复用方法、按变化续接。文件更新不代表运行会话已加载。

可配置基线：每小时通知与选定邮件，每 6 小时关注新 issue，每 24 小时开放／未完成对象兜底。接续同来源／范围未完 pass，不叠加；独立批次可并行，无变化复用已有处理。

完整抓取并处理或可靠保留后才推进位置；不发邮件、不改已读／订阅、不扩大邮箱范围。调度不证明覆盖，暂停保持暂停；资源处置、私密材料和备份按授权边界执行。

Complete scope. Keep instructions concise.

Prepare and assemble bounded Workers; dispatch, wait, integrate, continue, hand off or recover through native harness capabilities. Use native forge CLIs and scoped repository rules. Roles define responsibilities; templates stay together; state is direct Markdown.

Discover and directly assign new-repository work, audit assigned targets, reassess contributions, handle incremental feedback and run recurring passes. Capture followed issues, notifications/selected mail and open/unfinished objects under separate positions.

Prove actual-use/document errors and discuss ordinary unsettled contracts. Report every new security finding privately, never through public issues; retain protected evidence/blockers without an authorized private channel unless explicit category/scope-specific abandonment applies. Repair, validate, publish and follow up on ordinary work; consolidate or withdraw only within authority.

Maintainers triage issues, review/amend/merge PRs under current rights/settings, audit actual use/documents and revise code. Retain only actual-use coverage and essential CI/tests. Assigned PR review adds no universal pre-publication gate.

Write minimal records; migrate, reconcile/recover/reclassify history and publish reviewed backups when requested. Apply user-selected exclusions before selecting or continuing GitHub work, preserving existing objects/history. Check resources every pass. Keep authority explicit, one writer, native execution and direct Markdown; trust internal contracts and usable finals, keep private material confidential and apply storage retention paths, report incomplete outcomes accurately.

面向多 agent harness 的仓库维护 Skill：按范围与权限组装 Worker，完成发现、调查、交付和持续跟进；状态直接写 Markdown。

名单选范围。
每库记录存事实。

三个成员名单

新库待处理、旧库历史全表、分组关注名单。名单只保存成员；关注组允许重合，扫描去重并集。

共享事实，本地过程

每库写入者维护根 state.md 与本机 work/work.md；Coordinator 负责全局记录，指定发布者串行操作 Git。unfinished.md 仅导航，不是完整范围或授权。

每库一个目录

统一位于 state/repositories/<host>/<namespace>/<repo>/。只共享审阅后的 state.md；work/ 存笔记、多个 checkout 和 tmp，全部忽略。不递归上传或把执行材料当作状态。

来源独立，隐私隔离

通知与关注扫描位置在 read-positions.md，邮箱位置在 private/。保留原生边界，正文实时读，不复制交互数据库。

全部流程。
精要指派。

W保全证据并交接资源，不删checkout/tmp；C确认原writer及进程停止后执行授权清理；S统筹容量。显式授权可允许任务独占可重建依赖／构建产物及普通Git对象只读标记处置；源码／证据、共享缓存、工具链和访问控制仍受保护。

每次唤醒接续整个职责：整合后实际派发可行工作、等待真实在途，或保留确切阻碍／完成依据。摘要不等于补位。显式授权的心跳仅归Supervisor；暂停日程和项目单写入者边界不变。

准备目标、范围、权限和资源；Coordinator 选择形态与方法，用集中模板组装 Worker。每个任务一次派发、整合，续办只传变化；必要时交接或局部恢复。

等待前利用实际 backend 的授权容量，逐项完成补位，不等整批。优先级不是屏障，强制阶段门保留明确范围；有限批次／父 turn 结束不等于全范围完成或后代停止。Drain 禁补位并让已接受工作跑完；取消后确认相关 writer 停止才替换。不制造工作凑槽。完整独立输入可在其他捕获继续时推进；缺证据先本地恢复，再在原授权内补缺，来源位置仍须满足完整性门槛。任务完成解除默认 Worker／模型绑定；复用证据，仅在适合时作同任务有限续办。T3区分任务与线程；Pi使用宿主委派，不使用 subagent 插件及其容量规则。

按任务和动作加载规则：复用完整当前文本，同轮批量补读启动缺失项，在动作前加载条件方法；链接不要求递归阅读。叶 Worker 接收适用边界，不通读协调员简报。捕获验证来源，纯元数据工作不 clone／测试，修复保留受影响和强制检查。Coordinator 检查范围与覆盖，不二次验收工程；权限、隐私、歧义对账和保存门槛不减。

五类形态：发现入库、新库审计、既有投稿复审、增量反馈、持续巡查。增量来源：关注新 issue、通知与选定邮件、开放与未完成对象。抓取去重，按库指派，分别维护位置。

沿实际使用与文档事实查错；普通契约未定时据证讨论。所有新安全发现只走私有报告，不发公开 issue；无可用授权私有渠道时保留证据与阻塞。普通修复在完成指定审计后集中验证、投稿，再处理反馈、合并同根因或授权撤回。

记录只写实质变化；按请求迁移、核对历史、恢复或重分类、审阅后备份。处置使用或分配的资源，包括阻塞／无变化情况；无资源时省略空检查。区分覆盖、交付、解决和释放。

Maintainer 在授权管理／自有库中处理 issue、审查 PR、按当前权限与设置追加 commit 和合并；从实际使用与文档审计出发修订代码，精简冗余 CI/测试，只保留真实使用覆盖与基本检查。

范围与权限明确，默认串行；同资源单写入者。选择或继续 GitHub 工作前应用用户指定排除规则，保留已有对象与历史。依据实际使用与契约行动，禁止防御性编程，信任内部契约并保留必要边界校验。每个任务一次充分派发、增量续办、信任可用结果；保留未知与私密材料，如实报告成果和未完成工作。

roles/ 定义职责，prompts/ 集中启动、续办和交接。可读文件按需加载，否则传完整适用正文。Harness 按原生能力接入；无隐式权限、任务、计划或额外编排服务。

有界巡查。
可靠接续。

可配置基线：每小时通知与选定邮件，每 6 小时关注新 issue，每 24 小时开放／未完成对象兜底。接续同来源／范围未完 pass，不叠加；独立批次可并行，无变化复用已有处理。

完整抓取并处理或可靠保留后才推进位置；不发邮件、不改已读／订阅、不扩大邮箱范围。调度不证明覆盖，暂停保持暂停；资源处置、私密材料和备份按授权边界执行。

Complete scope. Keep instructions concise.

Prepare and assemble bounded Workers; dispatch, wait, integrate, continue, hand off or recover through native harness capabilities. Use native forge CLIs and scoped repository rules. Roles define responsibilities; templates stay together; state is direct Markdown.

Discover/admit, audit new targets, reassess contributions, handle incremental feedback and run recurring passes. Capture followed issues, notifications/selected mail and open/unfinished objects under separate positions.

Prove actual-use/document errors and discuss ordinary unsettled contracts. Report every new security finding privately, never through public issues; retain protected evidence/blockers without an authorized private channel. Repair, validate, publish and follow up on ordinary work; consolidate or withdraw only within authority.

Maintainers triage issues, review/amend/merge PRs under current rights/settings, audit actual use/documents and revise code. Retain only actual-use coverage and essential CI/tests. Assigned PR review adds no universal pre-publication gate.

Write minimal records; migrate, reconcile/recover/reclassify history and publish reviewed backups when requested. Apply user-selected exclusions before selecting or continuing GitHub work, preserving existing objects/history. Check resources every pass. Keep authority explicit, one writer, native execution and direct Markdown; trust internal contracts and usable finals, preserve private/unknown work, report incomplete outcomes accurately.
